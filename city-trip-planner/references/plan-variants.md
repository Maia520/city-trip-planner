# ABC 三档方案生成策略

> ABC 不是"好 / 中 / 差"，而是三种目标函数下的最优解。
> 默认推荐 **B 舒适版**，A 与 C 各有独立的最优场景。

## 1. 命名原则

| 档位 | 名称 | 目标函数 | 适合谁 | 什么时候它才是真最优 |
|---|---|---|---|---|
| A | 尽兴版 | 体验最优、强度最高 | 体力好、无老人幼儿、想一次玩透 | 青年结伴、无娃情侣、外地专程打卡 |
| B | 舒适版（推荐） | 均衡省力、全员适配 | 大多数家庭、带娃或带老人、时间有限 | 多数真实场景 |
| C | 省心版 | 低预算、低风险、可随时撤退 | 雨天、高温、体力不足、只想散心 | 天气差、老人疲倦、行程不确定 |

禁止使用"旗舰 / 标准 / 缩水""好 / 中 / 差"等命名。C 档一旦被感知为次品，就不会被选，三档会退化为"一个真选项 + 两个陪衬"。

## 2. 三档可比较的硬指标

输出必须给同一组指标，否则用户感知不到差别。

| 指标 | A 尽兴版 | B 舒适版 | C 省心版 |
|---|---|---|---|
| 核心点位 | 5—7 个 | 3—4 个 | 2—3 个 |
| 全天步行 | 8—12 km | 5—7 km | 3—5 km |
| 累计爬升 | 200—400 m | ≤150 m | ≤50 m |
| 室内点位占比 | 20%—30% | 30%—40% | ≥50% |
| 交通方式 | 步行 + 打车/自驾 | 步行 + 地铁/公交 | 车行 + 短步行 |
| 排队暴露 | 高（热门项目） | 中（可预约） | 低（冷门/错峰） |
| 预约难度 | 高（提前 3—7 天） | 中（提前 1—2 天） | 低（免预约） |
| 撤退难度 | 高（行程绑定） | 中 | 低（随时可结束） |

脚本输出的 `comparison` 会给出：点位数、步行公里、缓冲、总时长、室内占比、是否在时间窗内、最晚返程。Agent 再补充预算、预约难度、在途时长等语义指标。

## 3. 生成顺序（七步）

1. **求可行域**：用硬约束（台阶、无障碍、排队、医疗、营业时间）过滤候选点位。
2. **定强度上限**：取最弱成员的步行/爬升/排队阈值 × 经验安全系数（0.85 / 0.92）。
3. **生成 B 档**：在强度上限内最大化"全员适配总分"，点位数量按 `trip_type` 取值。
4. **生成 A 档**：允许强度上浮 30%—40%，加入 1—2 个"高价值但高消耗"点位；若含 0—3 岁、61—70 或 70+，必须标注"不建议全员参加"，并给分线方案。
5. **生成 C 档**：室内占比 ≥50%、排队暴露最低、点位 2—3 个、交通以车行/短步行；同时作为雨天/高温备选。
6. **强制对比表**：见第 2 节。
7. **强制风险与免责**：硬约束命中项、未核验项、医疗可达性、天气依赖、预约截止时间。

## 4. 每档必须有一句"用 X 换 Y"

用户真正想知道的是"多花两小时、多走三公里，能换来什么"。

- A 档："多走 4 公里、多排 40 分钟队，换来日落时的山顶机位和完整老街动线。"
- B 档："少走 3 公里、少 1 个点，换来老人孩子都能走完、晚上不崩。"
- C 档："砍掉 2 个打卡点，换来雨天不湿鞋、随时能回酒店、预算降 40%。"

## 4.1 多代同游（70+ + 0–6 岁）的 ABC 校准

| 项目 | A 尽兴 | B 舒适 | C 省心 |
|---|---|---|---|
| 点位上限 | 4 | 3 | 2 |
| 步行系数 | ≤1.10 | 1.00 | 0.75 |
| 打车阈值 | 超过 1.2 km 打车 | 超过 1.2 km 打车 | 超过 1.2 km 打车 |
| 午休 | 90 分钟强制 | 90 分钟强制 | 90 分钟强制 |
| 定位 | 分线版（成人线） | 默认推荐 | 雨天/老人疲倦时 |

A 档不再默认全员参加；B 档是"经常带 70 岁父母 + 5 岁孩子"的主推档。若行程在 12:00 前结束，不强行插入午休段；若延长到下午，必须保留 12:00–14:30。

## 5. 本地与外地旅游的差异

| 维度 | 本地 / 一日游 | 外地 / 多日游 |
|---|---|---|
| 决策成本 | 低，容错高 | 高，沉没成本大 |
| 体力分配 | 单日爆发 | 连续累积，第三天最危险 |
| 交通接驳 | 30 分钟内 | 落地 2—4 小时，首末日要轻安排 |
| 景点密度 | 2—4 个，可临时增减 | 每天 2—3 个，需提前预约 |
| 打卡 vs 深度 | 可出片优先 | 体验优先 |
| 风险 | 低，可随时回家 | 高，必须有撤退路线 |

**底层差别是"退出成本"。** 本地默认"探索模式"（多点位、低确定性）；外地默认"保障模式"（少点位、高确定性、强预案）。外地的第一小时（接驳、入住、第一顿饭）应单独设计为低强度缓冲段。

## 6. 默认值即产品价值观

写进产品说明，让用户知道"它为什么保守"：

- 默认 **B 档**，而不是 A 档；
- 默认 **0.85 安全系数**（熟练照护者 0.92）；
- 默认 **12:00—14:30 不排程**（幼儿、老人、多代同游）；
- 默认 **未核验点位不超过 20%**。

## 7. 分档常见陷阱

1. **把 C 档写成"缩水版"**：C 档的价值是"低风险可撤退"，不是"少花钱的将就"。
2. **三档只改点位数量**：必须同时改变步行、室内占比、交通、排队暴露，否则感知不到差异。
3. **A 档默认推荐**：第一次使用就超负荷，会失去信任。
4. **把"亲子友好/长辈友好"当成 C 档**：适配维度应与强度轴分开，用"舒适版（长辈友好）"这样的组合标签。
5. **不写排除理由**：只说排了什么，不说为什么没排，用户会怀疑漏项。

## 8. 脚本参数

```bash
# 默认输出 ABC 三档
python "$SKILL_ROOT/scripts/plan_route.py" --input itinerary.json --output route.json

# 只要单档（B 舒适版）
python "$SKILL_ROOT/scripts/plan_route.py" --input itinerary.json --plans 1
```

档位参数在 `plan_route.py` 的 `VARIANTS` 中：A 步行系数 1.30、B 1.00、C 0.75；缓冲增量 A -0.05、B 0、C +0.10；打车阈值倍数 A 1.5、B 1.0、C 0.6。可按城市与用户反馈校准。
